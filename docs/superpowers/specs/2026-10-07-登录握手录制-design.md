# 登录握手与认证失败的录制 / 回放设计规格（层 D 补完）

- 日期：2026-10-07
- 上游：`docs/superpowers/plans/2026-10-07-层D-录制回放.md`（层 D 录制回放）
- 状态：设计已获用户批准，待实现（实现前需先审本文件）
- 目标设备：小米「小胖」路由器（XiaoQiang），OpenWrt 底子，BusyBox v1.25.1
- 关联代码：`modules/router_admin/{recorder,replay,telnet,workers}.py`

## 1. 问题与背景

层 D 交付了「录制 → 回放」：`RecordingSession` 包住 `TelnetSession`，把 `run()` /
`run_batch()` 的收发落成 `steps: [{send, recv}]`，`ReplaySession` 严格按序比对重放。
开发日志第四节第 1 条记下了两个**结构性缺口**：

1. **登录握手录不到**：`TelnetSession.open()` → `_login()` 走的是裸 `_send` / `_recv`，
   **不经 `run()`**；而 `RecordingSession` 只装饰 `open/close/connected/run/run_batch`，
   其余属性经 `__getattr__`（`recorder.py:57-64`）**裸透传**给内层。因此「在外层实现
   `_send`/`_recv` 去记录」这条路根本不会被调用——`_login` 是内层对象的方法，用的是
   **内层**的 `self._send`/`self._recv`。接缝只能开在 `TelnetSession` 内部。
2. **认证失败不留痕**：`RecordingSession.run()` 先执行后 `append`（`recorder.py:83-89`），
   异常路径零记录；且失败发生在 `open()` 里，`flush()` 不检查步骤数，于是认证失败会
   落下一个 `steps: []` 的空文件。

由此还带出第三个缺口：回放侧 `ReplaySession` **没有握手概念**（`open()` 只重置
`_index`），录到的握手段无处消费，`replay.py:13-15` 又明令禁止放宽命令匹配。

## 2. 目标与非目标

### 目标

1. 录制**登录握手**（横幅 / 用户名发送 / 口令提示 / 口令发送 / 成功提示），口令位脱敏。
2. 录制**认证失败现场**（含路由器返回的原文，供人工查看），且失败不再是空文件。
3. 回放侧能消费握手段，并在「认证失败」录制上**确定性地复现失败**。
4. **不破坏既有 3 个夹具与既有断言的数字语义**（`consumed` / `remaining` 在测试里
   保持 0/1/3/5 等原值），旧 v1 录制仍可加载回放。

### 非目标

- 不给 `RecordingSession.run()` 加「异常也留命令」语义（与登录失败无关，且会改命令步的
  回放匹配语义）。
- 不修 `dump_recording` 的整体覆盖写（同一路径连录两个任务只剩最后一个）。
- 不做认证失败时的 UI 文案调整。
- 不做「录制回放 socket 层」（既有待办，另立任务）。
- 不把回放接到生产路径：`ReplaySession` 仍只在测试中使用。

## 3. 决策摘要

- **格式版本升 2，但接受 {1, 2}**（方案 A，用户已选）：版本号诚实表达「可能含握手段」，
  同时 v1 录制缺 `kind` 时默认 `command`，既有夹具不作废。
- **握手以显式 step + `kind` 表达**，不是「元数据里写一段握手」。
- **回放侧 `consumed` / `remaining` 仍只统计命令步**，握手消费另记 `login_consumed`；
  这是「既有断言数字不变」的关键。
- **失败只锁语义不锁文案**（用户已选）：回放抛 `TelnetLoginError`，测试断言类型与
  「口令阶段被拒」，路由器原文只留在 step 里。
- **录制是旁路**：回放/录制接缝的任何异常都不得改变生产登录行为。

## 4. 录制格式 v2

### 4.1 顶层

| 键 | 类型 | 说明 |
|---|---|---|
| `version` | int | 2（新录）。`load_recording` 接受 `{1, 2}`，其余（含 `bool`）抛 `ValueError`；缺省按 `RECORD_FORMAT_VERSION` 处理 |
| `device` / `firmware` / `captured_at` | str | 不变（缺省回填 `""`） |
| `steps` | list | 见下 |

### 4.2 step

```json
{"kind": "command", "send": "cat /etc/config/network 2>/dev/null", "recv": "..."}
```

| `kind` | `send` | `recv` | 含义 |
|---|---|---|---|
| `command` | 命令 | 输出 | `run()` / `run_batch()` 的收发（**默认值**：v1 无 `kind` 即此） |
| `login_prompt` | `""` | 横幅 / `login:` 提示 | 等待登录提示期间消费的文本 |
| `username_sent` | 登录用户名 | `""` | 发出的用户名 |
| `password_prompt` | `""` | `password:` 提示 | 等待口令提示期间消费的文本 |
| `password_sent` | 口令（**恒脱敏为 `***`**） | `""` | 发出的口令 |
| `login_ok` | `""` | 登录成功提示符 | 登录成功 |
| `login_error` | `""` | 路由器拒绝原文（脱敏后） | 认证失败，**终止** |

规则：

- 未知 `kind` → `ValueError`（夹具打错字当场暴露）。
- `send` / `recv` 缺省为 `""`；`load_recording` **保留** `kind`（当前实现会丢弃未知键，
  这是必须改的一处）。
- `dump_recording` 恒写 `kind`。
- 失败录制的步序列以 `login_error` 结尾，**无** `command` 步。
- 明文口令只允许存在于**内存**：`password_sent` 位的 `send` 在录制侧被强制脱敏为 `***`（见 §5.4）；任何 step 的任何字段都不得出现明文口令。

## 5. 录制侧设计

### 5.1 接缝：`TelnetSession.set_exchange_hook`

```python
def set_exchange_hook(self, hook):  # hook: Callable[[dict], None] | None
```

- **setter 而不是构造参数**：不动已有构造签名，默认 `None` → 现有一切行为、性能不变；
  既有大量 `TelnetSession(...)` 构造点零改动。
- 安装点在 `RecordingSession.open()`：**先** `inner.set_exchange_hook(self._record_exchange)`
  再 `inner.open()`（`hasattr` 守卫，假/替代内层无此方法时静默跳过）。

### 5.2 `_login` 上报点（顺序固定）

`_login` 是唯一上报处，共 6 种事件（成功路径 5 个 + 失败路径 1 个）：

1. `LOGIN_RE` 命中后 → `{"kind": "login_prompt", "recv": <本次消费文本>}`
2. `_send(user)` → `{"kind": "username_sent", "send": user}`
3. `PASSWORD_RE` 命中后 → `{"kind": "password_prompt", "recv": ...}`
4. `_send(password)` → `{"kind": "password_sent", "send": password}`
5. `PROMPT_RE` 命中 → `{"kind": "login_ok", "recv": ...}`
6. `BAD_LOGIN_RE` 命中 → `{"kind": "login_error", "recv": ...}`，**上报后**重抛
   `TelnetLoginError("认证失败：路由器拒绝了该口令")`

为拿到「本次消费文本」，`_await` 改为**返回**本次消费掉的文本（现存调用方忽略返回值，
零破坏）。

### 5.3 旁路铁律

hook 的调用被 `try/except Exception` 包住并吞掉（可记一条 debug 日志）。**录制失败绝不
能改变生产登录行为**——这是本设计的第一红线。

### 5.4 脱敏

`RecordingSession._record_exchange` 写入前对 `send` / `recv` 过现有 `redact(value, secrets)`
（`replay.py:164-174`），`secrets` 即 `wrap_if_recording(session, secrets=[...])` 传入的
登录口令（`workers.py:88`）。因此 `password_sent` 位恒为 `***`；凭据守卫
（`tests/test_layer_d_guardrail.py`）已同时扫 `send` 与 `recv` 两侧，正好接住。

### 5.5 失败落盘

不需要改 `flush()`：`login_error` 步已使 `steps` 非空；`workers.py` 的
`except TelnetError` → `finally: self._close()` → `RecordingSession.close()` → `flush()`
照常写出。认证失败现场不再是空文件。

## 6. 回放侧设计

### 6.1 `open(username=None, password=None)`

1. `_index = 0`；`_login_consumed = 0`；`_cmd_consumed = 0`（重置全部游标）。
2. 若序列前缀是握手段，则逐步消费到第一个 `command` 步（或结尾）：
   - `username_sent` / `password_sent`：调用方传了对应凭据时，用 `_matches(录制值, 凭据)`
     断言相等（口令位 `***` 即通配），不等则 `AssertionError("…（登录握手段）")`；
     未传则只消费。
   - `login_prompt` / `password_prompt` / `login_ok`：**消费但不比对**（回放侧没有真路由器
     可比），仅累计 `_login_consumed`。
   - `login_error`：累计后 `raise TelnetLoginError("认证失败：路由器拒绝了该口令")` —— 与生产
     同一句，测试只锁「口令阶段被拒」。
3. 遇到第一个 `command` 步即停。

### 6.2 唯一放宽点的界定

`_LOGIN_KINDS` 里**只收不发的回包步**允许「消费不比对」。这是本设计引入的**唯一**例外，
理由：握手的 `recv` 是路由器单向输出，回放侧无对应输入可比；且横幅含日期/版本等不稳定
文本，逐字比对本就不可行。**命令步的严格匹配语义不变**，`replay.py:13-15` 的红线仍守住。

### 6.3 游标语义（既有断言数字不变的关键）

| 属性 | v2 定义 | v1 等价于 |
|---|---|---|
| `consumed` | 已消费的**命令步**数（`run()` 累加 `_cmd_consumed`） | 原 `_index` |
| `remaining` | 命令步总数 − `consumed` | 原 `len(steps) - _index` |
| `login_consumed` | 已消费的握手段数（新增） | 恒 `0` |

`run()` 仍用原始步游标 `_index` 做匹配（`open()` 消费握手后它天然指向第一个命令步），
失配不前进、用尽即 `AssertionError` —— 逻辑不动。

## 7. 夹具与真机重录

### 7.1 夹具清单（4 个，均 v2）

| 文件 | 内容 |
|---|---|
| `router-xiaomi-4a.json` | 成功：握手 5 步 + 原 5 个命令步 |
| `router-xiaomi-4a-backup-empty.json` | 备份读回为空中止：同上握手 + 5 命令步（第 3 步 recv 空） |
| `router-xiaomi-4a-login-fail.json` | **新增**：`login_prompt → username_sent → password_prompt → password_sent → login_error`，无命令步 |

### 7.2 重录流程（文档化）

1. 口令从 DPAPI store 读（`store.load()` + `dpapi_unprotect`），**绝不写进脚本、命令行或
   命令历史**。
2. 设 `YZPLAN_RECORD_TELNET=<目标 JSON>`、`YZPLAN_RECORD_DEVICE=router-xiaomi-4a`。
3. 启动程序，在宽带账号 Tab 走一遍「读 → 改口令 → 保存」；失败夹具则**故意输错登录口令**
   触发认证失败。
4. 人工复查 JSON：`password_sent` 位须为 `***`；**PPPoE 账号 / MAC 要人工换成虚构值**
   （`recorder` 只脱敏 `secrets`，账号/MAC 会原样落盘，而仓库推到公开 GitHub/Gitee）。
5. 复查通过才拷入 `tests/fixtures/recordings/` 并提交。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| `open()` 消费握手改变了命令步游标 | `consumed` / `remaining` 只算命令步，既有数字不变；新增 `login_consumed` 表达握手 |
| 「消费不比对」被误解为整体放宽匹配 | §6.2 显式界定为唯一例外且只限 `_LOGIN_KINDS` 的只收回包步 |
| 横幅文本不稳定导致夹具脆 | 回包步不做断言；失败只锁语义不锁文案 |
| 录制接缝改坏生产登录 | hook 旁路铁律（§5.3）；hook 默认 `None` 时零行为变化 |
| 真实凭据泄漏进公开仓库 | 口令位由 `redact` 覆盖（且守卫双侧扫描）；账号/MAC 靠重录后人工替换（§7.2 第 4 步） |
| 版本升级使旧录制不可读 | 接受 `{1, 2}`，v1 缺 `kind` 默认 `command` |
