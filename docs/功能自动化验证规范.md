# YZplan 功能自动化验证规范

> 状态：草案（待评审） · 建立日期：2026-10-07
> 配套文档：`docs/测试编写规范.md`（测试写法纪律）、`AGENTS.md`（强制规范）

本文回答一个问题：**如何自动化验证 YZplan 的每个功能是否正常工作。**
它是设计/需求规范，不是实施计划；各批次实施时另出任务级计划（见第 8 节）。

---

## 1. 目标与成功标准

### 1.1 两个交付目标

| 目标 | 何时跑 | 允许的时间预算 | 对应层 |
|---|---|---|---|
| **回归安全网** | 每次改动、CI 内 | 秒级~分钟级 | A + B |
| **发布门禁** | 打版本前、本地/发布脚本 | 分钟级、允许接近真实 | C(发布形态) + D |

这两者**不能混在一个套件**里：混了要么太慢不能日常跑，要么太假不能当门禁。
规范按「何时跑」分层，每层有独立的验收标准。

### 1.2 「每个功能是否正常工作」的可操作定义

> 对每个已注册模块的每个**用户可见功能点**，存在至少一条自动化用例，
> 断言其**可观察副作用**（数据库行、配置文件、窗口/控件状态、返回值）。

「可观察副作用」而非「函数被调用」——这是本规范与「手写替身回固定值」做法的根本分野
（见第 3.3 节事故）。

### 1.3 成功标准（整体）

1. CI 每次运行产出覆盖率报告，「未覆盖行」清单可读、可按模块定位（层 A）。
2. 任一模块的 import 断裂 / UI 构造回归 / 生命周期 bug 在 CI 立即变红（层 B）。
3. 13 个模块各有 ≥1 条真实副作用断言的功能用例；存在一张功能矩阵，无「无归属」功能点（层 C）。
4. 路由器 telnet 等外部依赖用**录制回放**驱动，代码发出未录过的命令或对响应格式的假设变化时测试变红（层 D）。
5. 全部新增测试遵守 `AGENTS.md` 测试规范与 `docs/测试编写规范.md`，且已登记进 CI。

## 2. 现状（事实底座，2026-10-07 核实）

| 维度 | 现状 | 位置/证据 |
|---|---|---|
| 测试规模 | `tests/` 下 **122 个 `test_*.py`** + 独立冒烟脚本 `tests/smoke_test.py`（不被 pytest 收集） | `pytest.ini`（`python_files = test_*.py`） |
| 模块数 | **13 个模块**，各有用例 | `MODULE_INFO` 命中 13 处；`modules/registry.py` 自动发现 |
| CI | **4 个显式枚举的 pytest 进程**，`QT_QPA_PLATFORM=offscreen`；无 timeout、无覆盖率门槛；枚举漏了 `test_qpa_titlebar_render.py`（需真实窗口） | `.github/workflows/python-app.yml:35-53` |
| 覆盖率 | **完全不存在**：无 `pytest-cov`/`coverage`，无 `pyproject.toml`/`setup.cfg`/`.coveragerc`，CI 无阈值 | 全仓 grep 0 命中 |
| 全模块冒烟 | `smoke_test.py` 只建 `MainWindow` + 4 个 tab；**不启动模块、不调三个 UI 钩子** | `tests/smoke_test.py:27-34` |
| 模块契约 | `ModuleBase`：`start/stop` + `create_home_widget`/`create_settings_widget`/`create_page`（后三者可返回 None）；`ModuleRegistry`：`all()`/`enabled()`/`start_enabled()`/`stop_all()` | `modules/base.py`、`modules/registry.py` |
| 功能驱动接口 | MCP 服务器 **~71 个工具**，分 13 个切片；stdio + HTTP/SSE；GUI 类工具经 `data/mcp_inbox/*.json` IPC 投递给运行中的 GUI | `mcp_server/__init__.py:46-60`、`mcp_server/tools_*.py` |
| 外部资源测试 | 无自动化，或用手写「理想化」替身 | 见 3.3 |

### 2.1 测试替身现状（层 D 的动因）

替身**散落在各文件手写**，且是「理想化」的：

- `tests/test_router_wan.py:410-421` 的 `_S`：对任何写命令都回固定串 `"YZ_WRITE_OK"`。
- `tests/test_router_telnet.py:67` 的 `FakeSocket`。
- `tests/test_proxy_scanner.py:41` 的 `_FakeSocket`、`:58` 的 `_FakeResponse`。

**这不是风格问题，是安全隐患**：`test_router_wan.py:447-452` 记录了 2026-09-29 事故——
假 session 对任何命令都回 `YZ_WRITE_OK`，导致 4 份「备份」内容全是 `YZ_WRITE_OK` 而非配置正文，
写进了生产 `data/router_admin/backups/`，**安全网失效**。只要替身继续「回固定值」，
真实设备返回格式一变，测试照样绿。

## 3. 设计原则

1. **按「何时跑」分层**，每层独立可验收（第 4 节）。
2. **复用现有契约**，不另造轮子：模块枚举走 `ModuleRegistry`，功能驱动走 MCP，夹具走 `conftest.py`。
3. **断言可观察副作用**，禁止「回固定值」式替身（层 D 根治）。
4. **遵守 `AGENTS.md` 测试规范**：顶层无副作用、`QT_QPA_PLATFORM` 只 `setdefault`、QApplication 只在 `conftest` 建、
   持久化资源必须隔离、0xC0000005 路径用子进程隔离、`os.path.relpath` 跨盘符安全、新增测试文件必须登记 CI（规则 10）。
5. **新增文件纳入 CI**：层 B 顺带把 4 段手工枚举改成按 marker/目录选择，消除「加文件忘登记」这一易错点。

## 4. 分层设计

### 层 A — 覆盖率可见性（地基）

**目标**：量化「哪些功能被测到、哪些没有」，产出可定位的盲区清单。没有这一步，其余三层都是盲人摸象。

**接口/文件**
- `requirements.txt`：新增 `pytest-cov`。
- `pytest.ini`：保留现有 `addopts`，覆盖率参数放 CI 命令行（避免本地每次跑都算）。
- `.github/workflows/python-app.yml`：
  - 每个 chunk 进程设 `COVERAGE_FILE=coverage.chunkN`，加 `--cov=modules --cov=core --cov=mcp_server --cov=ui --cov-report=`。
  - 上传 `coverage.chunk*` 产物；新增一个合并步骤 `coverage combine` → `coverage report --show-missing` → `coverage xml`。

**关键决策**
- **先不设硬门槛**：先拿基线，再上 `--cov-fail-under`（低起步）。先卡数字会逼人写「为覆盖而覆盖」的测试。
- 报告**按模块目录分组**（`--cov=modules` 逐模块出「未覆盖行」），因为盲区是模块级的。

**验收**
- CI 运行结束产出 `coverage.xml` 与 `term-missing` 报告；
- 文档记录一份基线表（模块 → 覆盖率 → 主要未覆盖行）；
- 故意删掉某模块测试 → 该模块覆盖率显著下降。

---

### 层 B — 全模块无头冒烟（回归安全网核心）

**目标**：任一模块的 import / 注册 / UI 构造 / 生命周期回归，CI 立即变红，不必手工点开 13 个模块。

**接口/文件**
- 新增 `tests/test_smoke_all_modules.py`：

  1. **逐模块参数化**（`@pytest.mark.parametrize` 遍历 `ModuleRegistry.all()`）——每个模块一个用例：
     - 实例化成功；
     - `start()` 不抛异常且 `running` 为真；
     - `create_home_widget(parent)`、`create_settings_widget(parent)`、`create_page(parent)` 三钩子均不抛异常，
       且返回 `None` 或 `QWidget`；
     - `stop()` 不抛异常。
  2. **注册表健全性**：13 个模块全被发现；`id` 唯一；`MODULE_INFO` 字段齐全；均 `issubclass(ModuleBase)`。
  3. **主窗口装配**：`MainWindow.setup(HomeTab, ModulesTab, SettingsTab, AboutTab)` + 构造每个启用模块的 home widget
     （把 `smoke_test.py` 的手动流程 pytest 化）。

- 约束：用 `conftest.py` 的 `qapp` fixture（offscreen），依赖 autouse `_isolate_db`。
- 新增 marker `smoke`（注册在 `conftest.py::pytest_configure`）。

**关键决策**
- **默认模块必须能无头构造**。若某模块确实依赖外部资源而无法无头构造，必须**显式标注**
  （`xfail(reason=...)` 或模块声明标志），**不得静默 skip**——静默跳过恰好会掩盖回归。
- CI 选择方式改进：把 4 段手工枚举改为按 marker/目录选择（如 `pytest -m "not qpa"`），新增文件自动纳入。
  此改动需与 `AGENTS.md` 规则 10 一起更新。

**验收**
- 13 模块 ×（start / 三钩子 / stop）全绿；
- **负向验证**：临时破坏某模块 import 或 `create_home_widget`，冒烟测试变红（证明它真的在抓）。

---

### 层 C — 功能级 e2e（发布门禁核心）

**目标**：覆盖「真实交互 → 真实副作用」，作为「全功能可用」门禁。

**两个形态**
- **C1 无头 e2e（CI 可跑）**：每模块 ≥1 条用例，直接实例化模块/调用其 worker，走真实 store（临时库隔离），
  断言真实副作用；用 MCP 数据工具做检查/断言。
- **C2 GUI e2e（本地/发布前）**：新增发布脚本 `scripts/e2e_release.py`（或 `--e2e-gui` marker 的用例），
  启动真实应用/带全部窗口的 Qt 应用，经 MCP `mcp_inbox` IPC 投递 `gui_navigate` / 模块动作，
  断言窗口状态 + DB。需交互式桌面会话 → `skipif(CI)`。

**功能矩阵（驱动覆盖）**
- 以 MCP 的 ~71 个工具 + 模块 UI 钩子为**现成功能清单**，产出 `docs/功能矩阵.md`：
  行 = `模块 × 功能点`，列 = 测试 id / 形态（C1/C2/手工/外部）。
- **无「无归属」行**：每个功能点要么有自动化用例，要么显式标注为「手工」或「外部资源」并给理由。

**验收**
- 功能矩阵每行有归属；
- 每个模块至少一条 C1 用例断言真实副作用；
- C2 脚本在本地能把「打开菜单 → 执行动作 → 结论」跑通并留下证据。

---

### 层 D — 录制回放（外部资源的真机替身）

**目标**：把「手写理想化替身」升级为「真机录制、按序回放」，让外部集成静默失效在 CI 可见。

**录制格式**（`tests/fixtures/recordings/<device>.json`）
```json
{
  "device": "router-xiaomi-4a",
  "firmware": "OpenWrt 21.02",
  "captured_at": "2026-10-07",
  "steps": [
    {"send": "cat /etc/config/network", "recv": "config interface 'wan'\n..."},
    {"send": "uci set network.wan.password='***'", "recv": ""}
  ]
}
```

**接口/文件**
- Recorder：在真实 transport（telnet socket / HTTP session）外包一层，记录 `(send, recv)` 序列；
  由开关触发（如 `YZPLAN_RECORD_TELNET=<path>`）。**必须脱敏**（口令/密钥行写入前替换）。
- `ReplaySession`：实现 router workers 使用的会话接口（与现有 `_S.run(cmd)` 同形，drop-in 替换）。
  - **按序回放**；命令不匹配或序列用尽 → `AssertionError` 明确失败，**不再回固定值**。
- 首批目标：`modules/router_admin` 的 telnet（读/写 `/etc/config/network`、登录握手、认证失败）。
  替换 `test_router_wan.py` 的 `_S`、`test_router_telnet.py` 的 `FakeSocket`。
- 次批：代理真实 HTTP 响应（替换 `test_proxy_scanner.py` 的 `_FakeResponse`）。
- WebView2 / 提权若无法录制，退化为**契约测试**并在矩阵标注。

**关键决策**
- 录制夹具是**纯数据、无真机依赖**，可进 CI。
- 脱敏是硬要求：录制产物不得包含真实口令/密钥。

**验收**
- router 测试改用 `ReplaySession` 驱动；一份录制能完整回放；
- **负向验证**：改代码使其发出录制中不存在的命令 → 测试变红（证明它真在比对）。

## 5. 双目标映射

| 层 | 归属目标 | 跑在哪 | 频率 |
|---|---|---|---|
| A 覆盖率 | 两者（地基） | CI | 每次改动 |
| B 全模块冒烟 | 回归安全网 | CI | 每次改动 |
| C1 无头 e2e | 两者 | CI | 每次改动 |
| C2 GUI e2e | 发布门禁 | 本地/发布脚本 | 打版本前 |
| D 录制回放 | 两者 | CI（数据夹具） | 每次改动；录制时接真机一次 |

## 6. 分批实施路线

每批：先写失败测试（TDD）→ 实现 → 验证 → 登记 CI → 更新 `docs/开发日志.md` → 提交。

| 批次 | 内容 | 交付物 | 依赖 |
|---|---|---|---|
| **批次 1** | 层 A 覆盖率 | `pytest-cov` + CI 合并步骤 + 基线表 | — |
| **批次 2** | 层 B 全模块冒烟 + CI 枚举改进 | `tests/test_smoke_all_modules.py` + marker + CI 选择改造 | 批次 1（覆盖率可验证冒烟本身被计入） |
| **批次 3** | 层 D 录制回放（router 优先） | `ReplaySession` + 录制夹具 + Recorder + 替换手写替身 | 批次 2 |
| **批次 4** | 层 C 功能矩阵 + C1 无头 e2e + C2 发布脚本 | `docs/功能矩阵.md` + 各模块 e2e + `scripts/e2e_release.py` | 批次 1-3 |

**排序理由**：A 提供度量 → B 立起回归网 → D 消除最脆弱的外部替身隐患 → C 补门禁（依赖前三层的地基）。

## 7. 与现有规范的关系

- 所有新增测试遵守 `AGENTS.md`「测试规范（强制）」11 条与 `docs/测试编写规范.md`。
- **规则 10（新增测试文件必须登记 CI）**：批次 2 之前仍需手工登记；批次 2 的 CI 选择改造完成后，
  新文件自动纳入，规则 10 相应更新（保留「必须能被执行」的意图）。
- 0xC0000005 崩溃路径继续用子进程隔离（参考 `tests/test_todo_notes_ui.py` 的 `_YZ_SUBPROCESS_CHILD=1` 模式）。
- 持久化资源隔离统一走 `tests/conftest.py::_isolate_db`；新增 store/DB/配置须同步加入。

## 9. 风险与未决项

| 项 | 风险 | 处置 |
|---|---|---|
| 覆盖率跨 4 进程合并 | 产物合并可能漏文件 | 用 `coverage combine` 显式验证；有疑问时退化为单进程覆盖率作业 |
| 部分模块无法无头构造 | 冒烟误报 | 显式 `xfail(reason)`，先暴露真实耦合，不静默 skip |
| 录制脱敏 | 泄露真实口令 | 录制前置脱敏；提交前人工复查夹具 |
| GUI e2e 需交互会话 | CI 不可跑 | `skipif(CI)` + 发布脚本本地跑 |
| WebView2/提权不可录制 | 覆盖缺口 | 退化为契约测试并在功能矩阵标注 |
| 手工枚举改 marker 选择 | 可能漏收集 | 改造后以「测试总数不减少」为验收硬指标 |
